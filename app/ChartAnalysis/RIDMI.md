# GridBot / AlgoTrading

## Где находится авто-торговля
Папка `app/AlgoTrading` содержит основную реализацию автоматической торговли и интерфейса для GridBot.

### Ключевые файлы автоторговли
- `backend.py`
  - главный оркестратор приложения.
  - FastAPI сервер, маршруты API, WebSocket, фоновые задачи бота.
  - запускает `run_trading_cycle_for_account`, загружает конфиг, выполняет цикл анализа и выставления ордеров.
- `engine/plan.py`
  - основная логика расчёта сетки ордеров.
  - `build_order_plan` строит набор лимитных покупок и продаж для LONG режима.
  - `build_short_plan` строит план для SHORT режима.
- `engine/orders.py`
  - взаимодействует с брокерским API (Tinkoff Invest).
  - получает открытые ордера, рассчитывает стоимость, выставляет и отменяет лимитные/стоп-ордера.
- `engine/market_data.py`
  - собирает текущий контекст цены и параметры инструмента (типы, лоты, минимальный шаг, лимиты).
- `engine/portfolio.py`
  - получает текущие позиции и количество лотов в портфеле.
- `engine/history_engine.py`
  - синхронизирует историю торгов и состояние по инструменту.
  - возвращает последнюю цену покупки, среднюю цену покупки и последний трейд.
- `engine/scheduler.py`
  - проверяет торговые окна и время выставления лимитных ордеров.
  - отвечает за ребалансировку и режимы времени торговли.
- `engine/price_utils.py`
  - нормализация цены по шагу и минимальному шагу.
  - выбор масштаба цены для грида.
- `engine/storage.py`
  - сохраняет и читает локальное состояние бота и конфиги для каждого FIGI.
- `config.json` / `config.template.json`
  - настройки токена, счёта, торговых параметров и параметров для каждого тикера.

### Вспомогательные модули
- `logic/tinkoff.py` — работа с Tinkoff API, поиск инструментов, получение свечей и цен.
- `logic/ha_analyzer.py` — Heikin Ashi анализ, генерация сигналов.
- `logic/alerts.py` / `logic/api.py` / `logic/db.py` — PriceAlert, хранение, уведомления.
- `engine/dashboard_api.py` — аналитика портфеля и загрузка исторических данных.

## Как работает GridBot
Автоматическая торговля реализована как циклический бот в `backend.py`.

1. `backend.py` запускает фоновый поток `background_trade_worker`.
2. В каждой итерации бот читает конфигурацию пользователя и активные аккаунты.
3. Для каждого включённого `figi` он:
   - получает рыночные данные и параметры инструмента (`compute_price_context`);
   - считает текущее количество позиции и историю торгов;
   - определяет базовые цены покупки/продажи из последней покупки, средней цены и последней цены;
   - нормализует параметры грида (`normalize_prices`, `price_step`, `grid_min`, `grid_max`);
   - вызывает `build_order_plan` для LONG или `build_short_plan` для SHORT.
4. `build_order_plan` рассчитывает сетку:
   - число buy/sell ордеров (`buy_orders`, `sell_orders`);
   - шаг цены (`price_step` / `step`);
   - смещения вверх/вниз (`buy_offset_pct`, `sell_offset_pct`);
   - пределы диапазона `grid_min` / `grid_max`, `limit_down` / `limit_up`;
   - объём лота `order_qty` / `BUY_LOTS_PER_ORDER` / `SELL_LOTS_PER_ORDER`;
   - проверяет ограничения по марже и бюджету;
   - дополнительно отсекает ордера вне допустимого диапазона.
5. После построения плана бот выставляет лимитные ордера:
   - сначала покупку, если бюджет и класс актива позволяют;
   - затем продажу, если нет уже выставленных ордеров по тем же ценам.
6. Бот также следит за уже открытыми ордерами и отбрасывает дубли.
7. Для SHORT режима логика зеркальная, но ориентирована на короткие позиции.

## Что важно для нового визуального дизайна
Визуальный интерфейс должен отражать следующие элементы:

- Общая тема: тёмная, профессиональная панель трейдера с акцентами синего/жёлтого/зелёного.
- Разделение на зоны:
  - левое меню / watchlist для выбора тикера;
  - центральная область графиков с поддержкой сеток 1/2/4/6/9;
  - правая панель управления с вкладками.
- Верхняя панель:
  - глобальный поиск тикера;
  - выбор таймфрейма;
  - переключатель режима HA;
  - переключение компоновки графиков (сплит-сетка);
  - текущая цена и изменение за тикер;
  - быстрые кнопки: избранное, алерты, настройки, уведомления, панели.
- Центральный блок:
  - интерактивный график свечей;
  - панель инструментов рисования (горизонтальная линия, тренд, прямоугольник, Фибоначчи);
  - подсказка OHLC и время/объём.
- Правая панель:
  - вкладки: Alerts, Lines, Log, HA Analyzer, Bot;
  - вкладка Бот должна быть заметной и содержать состояние и кнопки управления автотрейдингом;
  - информационный карточный блок статуса бота;
  - лог бота в текстовом виде.
- Есть также отдельный `Seller Dashboard` интерфейс (`seller.html`), который может использоваться для глубокого мониторинга состояния торгов и ордеров.

## Визуальные метафоры и назначение
- Бот — это «работающий модуль», который живёт в правой панели и принимает команды Start / Stop / Cancel.
- Сетка графиков — важный элемент: разные компоновки позволяют следить за несколькими инструментами одновременно.
- Статус бота и лог должны выглядеть как «оперативный центр» с понятными карточками и бегущей строкой.
- Алёрты и линии — это вспомогательные слои, но они должны быть доступны через табы, не мешая основной торговой панели.

## Итог
Чтобы новый визуал был полезным агенту, важно понимать, что в `app/AlgoTrading`:
- Backend-логика грида располагается в `backend.py` + `engine/plan.py`;
- Ордерное взаимодействие — `engine/orders.py`;
- Торговые условия и рыночные параметры — `engine/market_data.py`, `engine/portfolio.py`, `engine/scheduler.py`, `engine/history_engine.py`;
- Основной UI в `frontend.html` — график + watchlist + бот-панель;
- Дополнительный продвинутый интерфейс — `seller.html` + `assets`.

Этот файл можно использовать как технико-визуальное ТЗ для нового дизайна GridBot в этой папке.
